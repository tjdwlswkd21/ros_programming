# Chapter 7, 8. DDS — 실습과제

## 1. 미들웨어(middleware)란 무엇인가?

미들웨어(Middleware)란 **운영체제(OS)와 응용 프로그램(Application) 사이에 위치하여, 서로 다른 시스템·프로그램·하드웨어 간의 통신과 데이터 교환을 중개해주는 소프트웨어 계층**을 말한다. 이름 그대로 "중간(middle)에 있는 소프트웨어(ware)"로, 응용 프로그램 개발자가 네트워크 프로토콜, 하드웨어 차이, 운영체제 차이 같은 저수준의 세부 사항을 직접 처리하지 않고도 다른 시스템과 손쉽게 통신할 수 있도록 추상화된 인터페이스를 제공한다.

미들웨어의 대표적인 역할은 다음과 같다.

- **이기종 시스템 간 연결**: 서로 다른 운영체제, 프로그래밍 언어, 하드웨어 플랫폼으로 만들어진 프로그램들이 서로 통신할 수 있게 해준다.
- **통신 기능의 추상화**: 네트워크 소켓, 프로토콜(TCP/UDP 등)과 같은 저수준 통신을 개발자가 직접 다루지 않도록 API 형태로 감싸준다.
- **재사용성 및 생산성 향상**: 통신, 메시지 큐, 트랜잭션 처리 같은 공통 기능을 미들웨어가 제공하므로, 개발자는 핵심 애플리케이션 로직 개발에 집중할 수 있다.

로봇 공학에서의 예로는 ROS2가 채택한 **DDS(Data Distribution Service)** 를 들 수 있는데, DDS는 노드(응용 프로그램) 간의 데이터 발행(publish)/구독(subscribe) 통신을 중개해주는 미들웨어 역할을 한다.

## 2. 분산컴퓨팅(distributed computing)에 대하여 조사하시오.

분산 컴퓨팅(Distributed Computing)이란, **네트워크로 연결된 여러 대의 독립적인 컴퓨터(노드)** 가 하나의 작업을 나누어 처리하고 그 결과를 종합하여, 사용자에게는 마치 하나의 통합된 시스템처럼 보이도록 하는 컴퓨팅 방식이다.

**주요 특징**

- **자원 공유**: 여러 노드가 CPU, 메모리, 데이터 등의 자원을 나누어 사용하거나 공유한다.
- **병행성(Concurrency)**: 여러 노드가 동시에 서로 다른 작업을 처리할 수 있다.
- **확장성(Scalability)**: 노드를 추가하는 것만으로 시스템 전체의 처리 능력을 확장할 수 있다.
- **내결함성(Fault Tolerance)**: 일부 노드에 장애가 발생하더라도, 다른 노드가 역할을 대신하거나 시스템 전체가 즉시 중단되지 않도록 설계할 수 있다.
- **투명성(Transparency)**: 사용자나 개발자가 자원이 물리적으로 어디에 있는지, 몇 대의 컴퓨터가 동작하고 있는지 신경 쓰지 않고 하나의 시스템처럼 사용할 수 있다.

**단점 및 고려사항**: 여러 노드가 네트워크를 통해 통신해야 하므로 지연(latency), 네트워크 장애, 동기화 문제, 데이터 일관성(consistency) 문제 등을 해결하기 위한 별도의 설계가 필요하다.

로봇 공학의 관점에서 보면, 하나의 로봇 안에서도 메인 컴퓨터·임베디드 보드·센서 모듈이 역할을 나누어 처리하거나, 여러 대의 로봇이 협업하여 임무를 수행하는 멀티 로봇 시스템이 대표적인 분산 컴퓨팅의 사례다. ROS2가 DDS라는 분산 미들웨어를 채택한 것도, 로봇 시스템을 단일 컴퓨터에 종속되지 않는 분산 구조로 확장하기 위함이다.

## 3. 네트워크 통신 기술에 대하여 조사하라.

네트워크 통신(Network Communication)은 물리적으로 떨어져 있는 둘 이상의 장치가 유·무선 매체를 통해 정해진 규약(프로토콜)에 따라 데이터를 주고받는 기술이다. 일반적으로 계층 구조(OSI 7계층 또는 TCP/IP 4계층 모델)로 설명된다.

- **물리 계층**: 이더넷 케이블, Wi-Fi 등 실제 전기 신호·전파를 통해 데이터를 전송하는 물리적 매체
- **네트워크 계층(IP)**: 각 장치에 IP 주소를 부여하고, 목적지까지 데이터가 전달될 경로를 결정
- **전송 계층(TCP/UDP)**: 데이터를 신뢰성 있게 전달할지(TCP, 연결 지향), 속도를 우선할지(UDP, 비연결 지향)를 결정
- **응용 계층**: 실제 애플리케이션이 사용하는 통신 규약(HTTP, MQTT, DDS-RTPS 등)

**대표적인 네트워크 통신 방식**

- **유니캐스트(Unicast)**: 하나의 송신자가 특정 하나의 수신자에게만 데이터를 전송
- **브로드캐스트(Broadcast)**: 하나의 송신자가 네트워크 내 모든 장치에 데이터를 전송
- **멀티캐스트(Multicast)**: 하나의 송신자가 특정 그룹(도메인)에 속한 여러 수신자에게만 데이터를 전송

로봇 공학 및 ROS2의 통신은 이 중 멀티캐스트 방식을 적극 활용한다. ROS2의 통신 미들웨어인 DDS는 일반적으로 UDP 기반의 신뢰성 있는 멀티캐스트(Reliable Multicast)를 구현하여, 특정 도메인에 속한 노드들에게만 효율적으로 데이터를 전달할 수 있게 한다. 이는 TCP 기반이었던 ROS1의 TCPROS와 대비되는 큰 변화로, 여러 노드가 동시에 참여하는 로봇 시스템에서 네트워크 자원을 훨씬 효율적으로 사용할 수 있게 해준다.

## 4. RTPS(real-time publish subscribe) 프로토콜에 대하여 조사하시오.

RTPS(Real-Time Publish-Subscribe Protocol)는 OMG(Object Management Group)가 표준화한 **DDS의 통신 규약(Wire Protocol)** 으로, 정확한 명칭은 **DDSI-RTPS(DDS Interoperability RTPS)** 이다. DDS가 "무엇을 할 수 있는가"에 대한 표준(API 수준의 상위 개념)이라면, RTPS는 "그 데이터를 실제 네트워크 상에서 어떻게 주고받는가"를 정의하는 하위 프로토콜이라고 볼 수 있다.

**RTPS의 주요 설계 목표(특징)**

- **플러그 앤 플레이 연결(Plug-and-play connectivity)**: 응용 프로그램이 네트워크에 들어오거나 나갈 때 별도의 설정 없이도 자동으로 서로를 탐색하고 연결할 수 있다.
- **성능 및 QoS 지원**: 신뢰성(reliable) 우선 또는 속도(best-effort) 우선 등, 실시간 애플리케이션에 맞게 통신 품질(QoS)을 세밀하게 조정할 수 있다.
- **내결함성(Fault Tolerance)**: 단일 장애점(Single Point of Failure)이 없는 구조로 설계되어, 특정 노드나 서버가 죽어도 나머지 통신에는 영향이 없다.
- **확장성(Modularity, Scalability)**: 소형 임베디드 기기부터 대규모 분산 시스템까지 폭넟게 적용 가능하다.
- **하위 전송 계층에 대한 최소 요구사항**: RTPS는 기본적으로 신뢰성이 보장되지 않는(best-effort) 연결 지향적이지 않은 전송(대표적으로 UDP)을 전제로 설계되었지만, 필요에 따라 TCP 등 다른 전송 계층 위에서도 동작할 수 있다.

RTPS는 이러한 특성 덕분에 실시간 데이터 전송을 보장하면서도 임베디드 시스템처럼 리소스가 제한된 환경에도 적용 가능하며, ROS2가 로봇처럼 실시간성이 중요한 분산 시스템에 DDS를 채택하는 핵심적인 이유 중 하나가 되었다.

## 5. DDS의 동적검색(Dynamic Discovery) 기능을 조사하시오.

DDS의 동적 검색(Dynamic Discovery)이란, 응용 프로그램(노드)이 **별도의 사전 설정(IP 주소, 포트 등) 없이도 네트워크 상에서 자신과 통신할 다른 참여자(Participant), 토픽, 데이터 타입을 자동으로 탐색하고 연결하는 기능**을 말한다.

**동작 방식 및 의의**

- 각 응용 프로그램은 DDS의 **Participant**로 취급되며, 네트워크에 참여하는 순간 자신이 어떤 토픽을 발행(publish)하거나 구독(subscribe)하는지를 주변에 알린다.
- 다른 참여자들도 동일한 방식으로 자신의 정보를 주고받으며, 서로 일치하는 토픽·데이터 타입을 가진 참여자끼리 자동으로 연결된다.
- 이 과정에서 사용자는 통신할 노드의 IP 주소나 포트를 미리 알거나 설정할 필요가 없으며, 운영체제나 하드웨어 플랫폼의 차이를 신경 쓸 필요도 없다.

**ROS1과의 비교**

- ROS1에서는 `roscore` 실행 시 함께 뜨는 **ROS Master**가 모든 노드의 이름을 등록하고, 각 노드가 주고받을 토픽·메시지의 정보를 관리·중개하는 역할을 담당했다. 그러나 이 구조에서는 ROS Master가 다운되거나 연결이 끊기면 노드 간 연결 정보 자체가 사라져 전체 시스템이 마비되는 단일 장애점(SPOF) 문제가 있었다.
- ROS2에서는 DDS의 동적 검색 기능을 사용함으로써 ROS Master라는 중앙 관리자가 완전히 사라졌고, 각 노드가 DDS를 통해 서로 직접 탐색하고 연결한다. 그 결과 특정 노드 하나에 문제가 생겨도 나머지 노드 간 통신에는 영향을 주지 않는 견고한(robust) 분산 구조가 가능해졌다.

## 6. ROS1과 ROS2의 통신 방식의 차이를 설명하시오.

| 구분 | ROS1 | ROS2 |
|---|---|---|
| 통신 미들웨어 | 자체 개발한 TCPROS (TCP 기반) | 산업 표준 미들웨어 DDS (DDSI-RTPS 프로토콜) |
| 노드 관리 방식 | ROS Master가 중앙에서 노드 이름 등록 및 토픽 매칭을 관리 (중앙집중형) | ROS Master 없이 DDS의 동적 검색(Dynamic Discovery)으로 노드 간 직접 탐색·연결 (분산형) |
| 단일 장애점 | ROS Master가 다운되면 전체 시스템 마비 | 특정 노드 장애가 전체 시스템에 영향을 주지 않음 |
| 전송 계층 | TCP 기반 | 일반적으로 UDP 기반의 신뢰성 있는 멀티캐스트 사용 (QoS로 TCP처럼 신뢰성 우선도 설정 가능) |
| QoS(통신 품질) 설정 | 별도 설정 기능 없음 | Reliability, Durability 등 다양한 QoS 파라미터를 세밀하게 설정 가능 |
| 보안 | 사실상 보안 기능 없음 | DDS-Security 사양 적용, SROS2 툴킷으로 보안 강화 |
| 메시지 정의 | msg, srv, action 파일 | 기존 msg, srv, action 외에 IDL(Interface Description Language) 지원 |

정리하면, ROS1은 **자체 개발한 TCP 기반 프로토콜(TCPROS)과 중앙 관리자(ROS Master)에 의존하는 중앙집중형 통신 구조**였던 반면, ROS2는 **산업 표준으로 검증된 DDS 미들웨어를 도입하여 중앙 관리자 없이 노드들이 자율적으로 서로를 탐색·연결하는 분산형 통신 구조**로 전환했다는 것이 가장 핵심적인 차이다.

## 7. ROS2에서 DDS 기술을 도입한 이유를 설명하라.

ROS2가 기존 ROS1의 TCPROS 방식을 버리고 DDS를 도입한 이유는 크게 다음과 같다.

1. **단일 장애점(SPOF) 제거**: ROS1의 ROS Master는 중앙에서 모든 노드를 관리하는 구조였기 때문에, Master가 죽으면 전체 시스템이 마비되는 치명적인 단점이 있었다. DDS의 동적 검색 기능을 통해 이 중앙 관리자를 없애고, 노드들이 자율적으로 서로를 탐색·연결하는 견고한 분산 구조를 확보할 수 있었다.
2. **산업 표준 채택을 통한 상업화·신뢰성 확보**: DDS는 OMG가 표준화하고, 항공·국방·의료·자동차 등 이미 검증된 산업 현장에서 오랫동안 사용되어 온 미들웨어다. TCPROS라는 독자 규격 대신 이러한 산업 표준을 사용함으로써 ROS2가 상업(제품) 분야로 확장되는 데 크게 기여했다.
3. **QoS(Quality of Service) 지원**: DDS는 신뢰성(reliable)과 속도(best-effort) 등 다양한 QoS 파라미터를 세밀하게 설정할 수 있어서, 애플리케이션 목적에 맞게 통신 품질을 유연하게 조절할 수 있다. 이는 TCPROS에는 없던 기능이다.
4. **실시간성 지원**: DDS의 RTPS 프로토콜은 실시간 데이터 전송을 보장하도록 설계되어, 실시간 운영체제(RTOS)나 임베디드 시스템에도 적용 가능하다.
5. **보안 강화**: DDS-Security 사양을 적용하고, ROS 커뮤니티가 SROS2 같은 보안 툴킷을 개발함으로써 통신 단계에서부터 보안 문제를 해결할 수 있게 되었다.
6. **멀티 플랫폼·벤더 선택 가능성**: DDS는 다양한 운영체제(Linux, Windows, macOS 등)와 프로그래밍 언어를 지원하며, ADLink, eProsima, RTI 등 여러 벤더의 구현체 중 원하는 것을 선택하여 사용할 수 있는 유연성을 제공한다.

즉, ROS2에서의 DDS 도입은 단순히 통신 라이브러리를 바꾼 것이 아니라, ROS를 학술 연구용 수준에서 벗어나 산업 현장에서 신뢰성 있게 사용할 수 있는 상용 로봇 플랫폼으로 발전시키기 위한 핵심적인 설계 결정이었다고 할 수 있다.

## 8. 비슷한 통신 기술인 MQTT와 DDS의 차이를 설명하라.

MQTT와 DDS는 둘 다 발행-구독(Publish-Subscribe) 패턴을 사용하는 통신 프로토콜이라는 공통점이 있지만, 설계 철학과 구조에서 뚜렷한 차이가 있다.

| 구분 | MQTT | DDS |
|---|---|---|
| 통신 구조 | **브로커(Broker) 기반**: 모든 메시지는 중앙의 브로커 서버를 거쳐 전달됨 | **브로커 없는(Broker-less) P2P 구조**: 참여자(Participant)들이 서로 직접 데이터를 주고받음 |
| 중심 개념 | **메시지 중심(Message-Centric)**: 토픽 문자열 단위로 메시지를 라우팅 | **데이터 중심(Data-Centric)**: 데이터의 종류, 형식, 전달 방식까지 미들웨어가 관리(DCPS 개념) |
| 전송 계층 | 주로 TCP/IP 기반 | 주로 UDP 기반의 신뢰성 있는 멀티캐스트 (필요 시 TCP도 가능) |
| 대상 환경 | 대역폭과 전력이 제한된 경량 IoT 디바이스, 저사양 네트워크 환경에 특화 | 실시간성·신뢰성이 중요한 대규모 분산 시스템(항공, 국방, 로봇, 자율주행 등)에 특화 |
| QoS(품질 제어) | 3단계의 비교적 단순한 QoS(0: 최대 한 번, 1: 최소 한 번, 2: 정확히 한 번) | 신뢰성, 지속성(Durability), 데드라인 등 매우 세분화된 다수의 QoS 항목 제공 |
| 확장성/단일 장애점 | 중앙 브로커가 병목이나 단일 장애점이 될 수 있음 | 중앙 서버가 없어 특정 노드 장애가 전체 시스템에 영향을 덜 줌 |
| 대표 활용 사례 | 스마트홈, 센서 데이터 수집 등 경량 IoT | 항공관제, 자율주행, 국방, 산업 자동화, 로봇(ROS2) 등 실시간·고신뢰 시스템 |

정리하면, MQTT는 **가볍고 단순한 브로커 기반 구조로 제한된 자원의 IoT 환경**에 적합한 반면, DDS는 **브로커 없이 참여자 간 직접 통신하는 데이터 중심 구조로, 실시간성과 높은 신뢰성이 요구되는 대규모 분산 시스템**에 적합하다. ROS2가 MQTT 대신 DDS를 채택한 이유도, 로봇처럼 다수의 노드가 실시간으로 방대한 데이터를 주고받아야 하는 환경에서는 중앙 브로커에 의존하지 않는 DDS의 구조가 더 적합했기 때문이다.
