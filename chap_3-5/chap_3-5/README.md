# Chapter 4. ROS2 특징 — 실습과제

## 1. ROS1과 ROS2의 통신방식의 관점에서 차이를 설명하라.

- **ROS1**: 노드 간 통신을 관리하기 위해 `roscore`를 실행해야 하며, 이때 함께 뜨는 **ROS Master**가 전체 노드의 이름 등록과 토픽/서비스 매칭을 중앙에서 담당한다. 통신 프로토콜로는 자체 개발한 **XMLRPC + TCPROS**를 사용한다. 이 구조는 ROS Master가 하나의 중앙 허브 역할을 하기 때문에, Master가 죽거나 네트워크 연결이 끊기면 전체 시스템의 노드 탐색·연결 기능이 마비되는 단일 장애점(SPOF) 문제가 있다.
- **ROS2**: 중앙 관리자인 ROS Master가 완전히 사라졌다. 대신 산업 표준 미들웨어인 **DDS(Data Distribution Service)**를 통신 계층으로 채택하여, 각 노드를 DDS의 **Participant**로 취급한다. DDS의 **Dynamic Discovery**(자동 검색) 기능을 이용해 노드들이 중앙 서버 없이도 서로를 직접 찾아 연결한다.
- 결과적으로 ROS1은 **중앙집중형(Master 기반)** 통신 구조인 반면, ROS2는 **분산형(P2P, Peer-to-Peer)** 통신 구조로, 특정 노드 하나가 죽어도 나머지 노드 간 통신에는 영향을 주지 않는다는 것이 핵심적인 차이다.

---

## 2. ROS1의 통신 미들웨어인 TCPROS와 ROS2의 통신 미들웨어인 DDS의 차이를 설명하라.

| 구분 | TCPROS (ROS1) | DDS (ROS2) |
|---|---|---|
| 개발 주체 | ROS 자체 개발(독자 프로토콜) | OMG(Object Management Group)가 표준화한 산업 표준 |
| 전송 방식 | TCP 기반 단일 방식 | RTPS(Real-Time Publish-Subscribe Protocol) 기반, 벤더에 따라 UDP 등도 활용 |
| 노드 탐색 | ROS Master가 중앙에서 이름/타입을 매칭해줘야 통신 가능 | Dynamic Discovery로 노드 간 자동 탐색·연결 (Master 불필요) |
| 서비스 품질(QoS) | 별도 QoS 설정 기능 없음 | Reliability, Durability 등 QoS 파라미터를 세밀하게 설정 가능(신뢰성 우선 or 속도 우선 선택 가능) |
| 보안 | 사실상 보안 기능 없음(포트 노출 시 취약) | DDS-Security 사양 적용, SROS2 툴킷으로 보안 강화 가능 |
| 사용 분야 | 학술/연구용 수준 | 항공, 자동차 등 산업 현장에서 이미 검증된 표준 프로토콜 |
| 실시간성 | 지원하지 않음 | RTPS 및 실시간 OS 조합 시 실시간성 지원 가능 |

정리하면, TCPROS는 ROS1을 위해 만든 **자체 통신 방식**이었지만, DDS는 로보틱스 이전부터 항공·국방 등 산업계에서 검증되어 온 **표준 미들웨어**로, QoS 제어·보안·탈중앙화된 노드 탐색 등 TCPROS에는 없던 기능들을 제공한다는 점이 가장 큰 차이다.

## 3. 실시간 시스템(real time system)의 정의를 조사하라.

실시간 시스템(Real-Time System)이란 **연산 결과의 논리적 정확성(Logical Correctness)뿐 아니라, 그 결과가 정해진 시간 제약 안에 산출되는지(Temporal Correctness)까지 만족해야 하는 시스템**을 말한다. 즉, 답이 맞더라도 정해진 시간(데드라인, deadline) 내에 나오지 않으면 그 결과는 의미가 없어지거나 시스템에 문제를 일으킨다는 점이 일반적인 컴퓨팅 시스템과 다른 부분이다.

실시간 시스템은 데드라인을 지키지 못했을 때의 심각도에 따라 보통 두 가지로 구분된다.

- **경성 실시간 시스템 (Hard Real-Time System)**: 데드라인을 지키지 못하면 시스템에 치명적인 결과를 초래한다. 예: 무기 제어, 원자력 발전소 제어, 철도 자동제어, 자동차 에어백/브레이크 제어 등.
- **연성 실시간 시스템 (Soft Real-Time System)**: 데드라인을 지키지 못해도 시스템 전체에 치명적인 영향은 없고, 성능이나 품질(QoS)이 일시적으로 저하되는 수준에 그친다. 예: 동영상 스트리밍(프레임이 몇 개 누락되어도 재생 자체는 계속됨).

로봇 공학에서는 모터 제어, 센서 값 수집·피드백처럼 정해진 주기 안에 처리되지 않으면 로봇의 동작이 불안정해지거나 위험해질 수 있는 영역에서 실시간성이 특히 중요하게 다뤄진다. ROS2는 DDS의 RTPS 프로토콜, 실시간 운영체제(RTOS), 잘 작성된 실시간 코드를 함께 사용하는 것을 전제로 이러한 실시간성을 지원하고자 한다.

## 4. GPL 라이선스와 Apache 2.0 라이선스의 차이를 설명하라.

두 라이선스 모두 오픈소스 라이선스이지만, 가장 큰 차이는 **카피레프트(Copyleft) 적용 여부와 강도**에 있다.

- **GPL (GNU General Public License)**: **강한 카피레프트(Strong Copyleft)** 라이선스다. GPL로 배포된 코드를 수정하거나, 그 코드를 포함한 더 큰 프로그램을 만들어 배포할 경우, 그 결과물 전체를 동일한 GPL 라이선스로 공개해야 한다. 즉, GPL 코드가 조금이라도 섞이면 전체 소스코드를 공개할 의무가 따라오기 때문에, 상용 소프트웨어에 자유롭게 섞어 쓰기가 까다롭다.
- **Apache License 2.0**: **허용적(Permissive) 라이선스**로, 카피레프트 조항이 없다. 소스코드를 수정하거나 다른 프로젝트에 포함시켜 배포하더라도, 수정한 코드 전체를 같은 라이선스로 공개할 의무가 없다. 즉, 상업적 목적의 비공개(폐쇄형) 소프트웨어에도 비교적 자유롭게 포함시켜 사용할 수 있다. 다만 원저작물에 대한 라이선스 고지, 저작권 표시, 변경 사항 명시 등의 절차적 의무는 있으며, 특허권(patent) 관련 조항도 포함되어 있어 기여자의 특허로부터 사용자를 보호해주는 특징이 있다.

정리하면, GPL은 "가져다 쓰면 너의 코드도 공개해야 한다"는 **강제적 공유** 성격이 강한 반면, Apache 2.0은 "가져다 써도 되고 공개하지 않아도 된다"는 **자유로운 재사용** 성격이 강하다. ROS2가 Apache 2.0을 채택한 이유도, 기업들이 지적 재산권 부담 없이 자유롭게 상용 제품에 ROS2를 활용할 수 있도록 하기 위함이다.

## 5. 멀티 프로세싱을 설명하라.

멀티 프로세싱(Multi-Processing)이란 하나의 컴퓨터(또는 시스템)에서 **여러 개의 프로세스(Process)를 동시에 실행**시키는 처리 방식을 말한다. 하나의 CPU 코어에서 여러 프로세스를 매우 짧은 시간 단위로 번갈아 실행하며 마치 동시에 실행되는 것처럼 보이게 하거나(시분할, Time-sharing), 멀티코어 CPU를 활용해 실제로 여러 프로세스를 물리적으로 동시에 실행할 수도 있다.

각 프로세스는 자신만의 독립된 메모리 공간을 가지므로, 한 프로세스에 오류가 나더라도 다른 프로세스에 직접적인 영향을 주지 않는다는 장점(안정성)이 있는 반면, 프로세스 간 데이터를 주고받으려면 IPC(Inter-Process Communication, 프로세스 간 통신) 기법이 별도로 필요하다는 특징이 있다.

ROS의 맥락에서 보면, ROS1/ROS2의 각 노드(node)는 기본적으로 하나의 독립된 프로세스로 실행되며, 노드 간 데이터 교환(토픽, 서비스 등)은 결국 이러한 프로세스 간 통신을 로봇 응용 프로그램 수준에서 추상화해 제공하는 것이라고 볼 수 있다.

## 6. 분산 컴퓨팅을 설명하라.

분산 컴퓨팅(Distributed Computing)이란 하나의 작업을 **네트워크로 연결된 여러 대의 컴퓨터(노드)** 가 나누어 처리하고, 그 결과를 종합하여 하나의 시스템처럼 동작하게 만드는 컴퓨팅 방식이다. 물리적으로 떨어져 있는 여러 컴퓨터가 협력하여 계산을 수행하기 때문에, 사용자 입장에서는 여러 대의 컴퓨터가 마치 하나의 시스템처럼 보이게 된다.

분산 컴퓨팅의 주요 특징은 다음과 같다.

- **확장성(Scalability)**: 컴퓨터(노드)를 추가함으로써 전체 처리 능력을 확장할 수 있다.
- **병렬 처리**: 여러 노드가 동시에 작업을 나누어 처리하므로 대규모 작업을 빠르게 처리할 수 있다.
- **내결함성(Fault Tolerance)**: 일부 노드에 장애가 발생해도 다른 노드들이 작업을 이어받아 전체 시스템이 계속 동작할 수 있도록 설계할 수 있다.
- **통신 필요성**: 각 노드는 독립적으로 동작하지만, 작업을 조율하고 데이터를 주고받기 위해 네트워크 통신이 필수적이다.

로봇 공학에서는 하나의 로봇 안에서도 여러 대의 컴퓨터(예: 메인 PC, 임베디드 보드, 센서용 마이크로컨트롤러)가 역할을 나누어 처리하거나, 복수의 로봇이 협업하여 임무를 수행하는 경우가 많은데, ROS2가 지향하는 "복수대의 로봇", "다중 도메인" 지원이 바로 이러한 분산 컴퓨팅 환경을 염두에 둔 설계라고 할 수 있다.

## 7. 네트워크 통신을 설명하라.

네트워크 통신(Network Communication)이란 물리적으로 분리된 둘 이상의 장치(컴퓨터, 로봇, 센서 등)가 유선 또는 무선 매체를 통해 연결되어, 정해진 규약(프로토콜)에 따라 데이터를 주고받는 것을 말한다.

일반적으로 네트워크 통신은 계층 구조(OSI 7계층 또는 TCP/IP 4계층 모델)로 이해된다.

- **물리 계층**: 실제 전기 신호나 전파를 통해 비트를 전송하는 물리적인 매체(이더넷 케이블, Wi-Fi 등)
- **네트워크 계층(IP)**: 각 장치를 구분하는 IP 주소를 부여하고, 목적지까지 데이터가 도달할 경로를 결정
- **전송 계층(TCP/UDP)**: 데이터를 신뢰성 있게 전달할지(TCP), 속도를 우선할지(UDP) 등 전송 방식을 결정
- **응용 계층**: 실제 애플리케이션이 사용하는 통신 규약(HTTP, DDS-RTPS 등)

이러한 네트워크 통신 위에서 여러 장치가 데이터를 주고받을 수 있기 때문에 분산 컴퓨팅, 클라우드 서비스, IoT, 그리고 ROS/ROS2의 노드 간 통신 같은 것들이 가능해진다. 특히 ROS2는 DDS의 RTPS(Real-Time Publish-Subscribe Protocol)를 이용해 UDP/TCP 기반의 네트워크 통신 위에서 퍼블리셔-구독자(Pub-Sub) 방식의 통신을 구현하며, QoS 설정을 통해 신뢰성과 속도 중 원하는 방향으로 통신 품질을 조절할 수 있다.
