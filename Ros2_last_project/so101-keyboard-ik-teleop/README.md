# SO-101 키보드 손목 위치 제어 로봇팔 (ROS 2)

## 1. 작품명

**키보드로 손목 위치(x, y, z)를 정하고 손목 기울기를 유지하며 움직이는 SO-101 로봇팔**
— 역기구학(IK) 기반 ROS 2(C++) 텔레오퍼레이션

레포 이름: `so101-keyboard-ik-teleop`

---

## 2. 작품설명

LeRobot SO-101 로봇팔을 키보드로 조종하는 작품이다.
보통은 관절 하나하나의 각도를 따로 돌려야 하는데, 이 작품은 **"손목(아래에서 4번째 관절, wrist_flex 축)이 어디로 가야 하는지"를 키로 정하면** 로봇이 알아서 관절 각도를 계산해서(역기구학) 움직인다.
물체를 **어떤 각도로 잡을지**는 ↑↓ 키로 손목 기울기를 정해서 따로 정하고, 이 기울기는 손목이 이동하는 동안에도 자동으로 유지된다. (켜고 끄는 옵션이다)
리더암(조종용 팔) 없이 키보드만으로 물건을 집어서 옮기는 것까지 하는 게 목표다.

### SO-101 관절 6개를 나눠서 조종한다

| 관절 (아래 → 위) | 조종 방법 | 설명 |
|---|---|---|
| shoulder_pan (베이스 회전) | **IK가 계산** | 손목 목표점의 좌우 방향을 보고 각도 결정 |
| shoulder_lift (어깨) | **IK가 계산** | 손목 목표점까지의 거리·높이를 보고 결정 |
| elbow_flex (팔꿈치) | **IK가 계산** | 위와 같음. 팔꿈치가 위로 가는 해만 쓴다 |
| wrist_flex (손목 위아래) | **↑ ↓ 키로 목표 기울기를 바꾸면 자동 계산** | 손목 각도 = 목표 기울기 − (어깨 + 팔꿈치). 이동 중에도 기울기가 유지됨 |
| wrist_roll (손목 회전) | **← → 키** | 한 바퀴(360°) 회전 |
| gripper (집게) | **Ctrl + A / Ctrl + D** | 닫기 / 열기 |

> IK가 푸는 건 pan, lift, elbow 3개이고, 이 3개가 **손목 위치**를 완전히 정한다. wrist_flex는 손목 위치에 영향을 못 주기 때문에 손목 위치와 기울기를 따로 정할 수 있다.

### 조작키

| 키 | 동작 |
|---|---|
| `W` / `S` | 손목 앞 / 뒤 (x) |
| `A` / `D` | 손목 왼쪽 / 오른쪽 (y) |
| `Ctrl + W` / `Ctrl + S` | 손목 위 / 아래 (z) |
| `↑` / `↓` | 목표 손목 기울기 위 / 아래 |
| `←` / `→` | 손목 회전 (반시계 / 시계) |
| `Ctrl + A` / `Ctrl + D` | 그리퍼 닫기 / 열기 |
| `T` | 기울기 유지 켜기 / 끄기 (기본값은 켜짐) |

- 키를 **누르고 있는 동안만** 움직이고, 떼면 그 자세로 멈춘다. 그래서 따로 정지 키는 없다. (서보는 자세를 유지한다)
- 두 키를 같이 누르면 두 방향이 합쳐져서 대각선으로 움직인다.
- `Ctrl`이 눌려 있으면 `W/A/S/D`는 이동이 아니라 Ctrl 조합 명령으로만 처리한다. (`Ctrl+A`가 왼쪽 이동으로도 인식되는 것을 막는다)
- 기울기 유지가 켜져 있어도 관절 한계 때문에 그 기울기를 못 만드는 위치가 있다. 이때는 **위치 이동이 우선**이고, 손목은 한계값에 멈춘다. (목표 기울기는 그대로 두었다가 가능해지면 다시 맞춘다)
- 키 이름과 이동 속도는 설정 파일로 따로 뺄 예정이다.
- 물체 잡는 순서: ① ↑↓로 잡을 기울기를 정한다 → ② WASD / Ctrl+W·S로 접근한다 → ③ Ctrl+A로 잡는다.

### 동작 흐름 (한 줄)

`키 입력 → 명령으로 해석 → 손목 목표 위치(x,y,z) 만들기 → 역기구학으로 관절각 계산 → 손목 기울기 계산 → 관절 한계·변화량 제한 → 모터 구동 → 현재 관절각 읽기`

자세한 블럭도와 데이터 흐름은 [개념설계](docs/concept-design.md)에 있다.

### ROS 2를 쓰는 부분 (필수 조건)

기능을 **노드 6개**로 나누고 **토픽**으로 데이터를 주고받는다. 수업에서 배우는 C++(rclcpp)로 만들고, LeRobot 모터 드라이버만 파이썬으로 둔다.

| 노드 | 언어 | 하는 일 |
|---|---|---|
| `keyboard_node` | C++ | 키 상태 읽기, 명령으로 해석 |
| `ik_node` | C++ | 목표 손목 위치 만들기, 역기구학, 순기구학 |
| `wrist_node` | C++ | 목표 기울기 유지, wrist_flex 계산 |
| `direct_node` | C++ | 손목 회전·그리퍼 목표 만들기 |
| `merge_node` | C++ | 6개 관절 취합, 관절 한계·변화량 제한 |
| `driver_node` | Python | LeRobot으로 모터에 보내고 현재 위치 읽기 |

- **launch 파일**과 **파라미터 파일**(`controller_params.yaml`)로 한 번에 실행하고 속도, 작업영역, 관절 한계, 기울기 유지 기본값을 바꾼다.
- 디버깅용(선택): `robot_state_publisher` + RViz2로 로봇 모델을 띄워서 확인한다. 조작에는 필요 없고, 목표·현재 손목 위치는 터미널 로그로도 볼 수 있다.

### 실행 환경

- 한 대의 PC에서 **WSL2 Ubuntu + ROS 2**로 실행한다. (SSH는 쓰지 않는다)
- 로봇은 USB로 PC에 꽂고 `usbipd-win`으로 WSL2에 연결한다.
- 키보드 창(GLFW)은 WSLg가 Windows 화면에 띄워준다. 우분투 데스크톱은 필요 없다.

## 3. 선정이유

- **관절 각도로 로봇을 움직이면 직관적이지 않다.** 사람은 "앞으로 조금, 위로 조금"처럼 위치로 생각하지 각도로 생각하지 않는다. 위치를 정하면 각도는 로봇이 계산하게 하고 싶었다.
- **물체를 잡을 각도를 직접 정할 수 있다.** 위치는 IK가 맡고, 기울기는 사람이 따로 정한다. 기울기는 이동 중에도 유지돼서 "이동했더니 각도가 안 맞는" 일이 없다.
- **역기구학을 직접 구현해서 눈으로 확인할 수 있다.** 어깨·팔꿈치 2링크 구조라 수식으로 바로 풀 수 있고(시뮬레이션 없이), 결과가 바로 로봇 움직임으로 보인다.
- **리더암 없이 조종할 수 있다.** LeRobot SO-101 기본 조종 방식은 리더암(똑같이 생긴 조종용 팔)을 손으로 움직이는 것인데, 키보드만 있으면 되니까 장비가 적게 든다.
- **ROS 2 수업 내용을 실제 로봇에 적용할 수 있다.** 노드/토픽/파라미터/launch를 C++로 한 프로젝트에서 다 쓴다. SO-101은 URDF와 파이썬 API가 공개돼 있고, ROS 2와 연결한 오픈소스 예제도 있어서 참고하면서 만들 수 있다.
- **키 배치를 설계하는 것도 재미있는 부분이다.** 위치는 왼손(WASD + Ctrl), 손목은 오른손(방향키)으로 나누면 직관적이면서 키 수도 관리할 수 있다.

### 까다로운 점과 해결 방법

1. **IK 기준점을 어디로 잡을 것인가 / 손목과 위치의 간섭.**
   처음에는 그리퍼 끝을 기준점으로 생각했는데, 그리퍼 끝은 손목 앞에 달려 있어서 `wrist_flex`가 바뀌면 끝점 위치도 같이 바뀐다. 그래서 **기준점을 4번째 관절(wrist_flex 축)의 위치(손목 점)** 로 정했다. 이 위치는 pan, lift, elbow 3개만으로 정해지고 wrist_flex와 상관이 없다.
   또 손목은 상대 각도라서 어깨·팔꿈치가 돌면 기울기가 같이 틀어진다. → ↑↓로 **목표 기울기**를 정하고, 손목 각도는 `목표 기울기 − (어깨 + 팔꿈치)`로 계속 다시 계산해서 기울기를 유지한다. (부호와 오프셋은 URDF 기준으로 맞춘다)
   남는 주의점: ① 손목 관절 한계 때문에 그 기울기를 못 만드는 위치가 생길 수 있다 → 위치 이동이 우선이고 손목은 한계값에 멈춘다. ② ↑↓를 누르면 그리퍼 끝이 손목 점 둘레로 원호를 그리며 움직인다.

2. **키 입력 방식.**
   터미널에서 키를 읽으면 키를 뗀 순간과 동시 입력을 알 수 없고 `Ctrl` 단독 입력도 못 받는다. → **GLFW 창**으로 키 상태를 읽는다. 창에 포커스가 있을 때만 키가 들어간다. (내 PC에서 WSLg 창이 키를 제대로 받는지 직접 확인 필요)

3. **Ctrl 조합 충돌.**
   `Ctrl+A`가 이동의 `A`로도 인식되면 안 된다. → `keyboard_node`가 Ctrl 조합을 **한 곳에서** 먼저 가려서 명령을 나눠 보낸다.

4. **도달할 수 없는 위치 / 특이점.**
   팔 길이보다 먼 곳, 베이스 바로 위(반지름 0 근처), 바닥 아래는 IK가 풀리지 않거나 관절이 갑자기 뒤집힌다.
   → 목표 위치를 만들 때 **작업영역 제한**(최대 거리, 최소 반지름, 최소 높이)을 걸고, IK가 실패하면 직전 값을 유지한다.

5. **관절 한계.**
   → 처음에 **캘리브레이션**으로 관절별 최소·최대각을 정하고, 그 값을 넘는 목표는 무시한다. (터틀심 창 크기처럼 그 밖으로 못 나가게)

6. **시작할 때 로봇이 튈 수 있다.**
   목표가 현재 위치와 다르면 첫 동작에서 로봇이 갑자기 움직인다.
   → 시작할 때 **현재 관절각을 읽어서 FK로 현재 손목 위치를 계산하고, 그 값을 첫 목표로 사용**한다.

7. **URDF 각도와 실제 로봇 각도가 다를 수 있다.**
   LeRobot은 기본이 도(degree), URDF는 라디안이고, 캘리브레이션에 따라 0점도 다를 수 있다. (내 로봇에서 직접 확인 필요)
   → 변환/오프셋을 한 곳에 모아 둔다. 링크 길이와 오프셋은 URDF 값에서 읽어 온다.

8. **WSL2에서 USB 로봇 연결.**
   → `usbipd attach --wsl`로 연결하고 `/dev/ttyACM0`가 보이는지 먼저 확인한다. (내 PC의 Windows 버전, `wsl --update` 상태 확인 필요)

## 정리

- **뭘 만드나**: 키보드로 SO-101 **손목(wrist_flex 축) 위치 (x, y, z)** 를 움직이고, 로봇이 관절 각도를 알아서 계산해서 따라가는 ROS 2(C++) 텔레오퍼레이션
- **조작**: `WASD`로 앞뒤·좌우, `Ctrl+W/S`로 위아래, `↑↓`로 목표 기울기, `←→`로 손목 회전(360°), `Ctrl+A/D`로 그리퍼 닫기/열기, `T`로 기울기 유지 켜기/끄기. 키를 떼면 멈춘다
- **IK 담당**: shoulder_pan, shoulder_lift, elbow_flex 3개가 손목 위치를 정하고, wrist_flex는 "목표 기울기 − (어깨 + 팔꿈치)"로 계산해서 이동 중에도 기울기를 유지 (옵션, 한계에 걸리면 위치 이동이 우선)
- **ROS 2**: 노드 6개(키 입력, 역기구학, 손목 유지, 직접 제어, 취합, 드라이버)를 토픽으로 연결하고, launch/파라미터로 실행. 드라이버만 파이썬, 나머지는 C++
- **환경**: WSL2 Ubuntu + usbipd + WSLg(GLFW 창), 한 대의 PC
- **까다로운 점**: IK 기준점과 손목 간섭, 키 입력 방식과 Ctrl 조합, 작업영역·특이점·관절 한계, 시작 시 튐, 각도 단위·오프셋, WSL2 USB 연결
